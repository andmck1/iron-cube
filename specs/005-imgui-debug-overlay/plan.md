# Implementation Plan: ImGui Debug Overlay

**Branch**: `005-imgui-debug-overlay` | **Date**: 2026-05-21 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/005-imgui-debug-overlay/spec.md`

## Summary

Integrate ImGui as a debug overlay layer in the Iron Cube rendering architecture. Introduce a layer stack pattern where each renderable component implements a common `ILayer` interface with `initialize()`, `render()`, and `shutdown()` methods. The application's main loop iterates through the layer stack, rendering the scene layer first, then the debug layer on top. The debug layer displays an FPS counter and interactive controls for modifying the triangle's transform (position, rotation, scale). ImGui integrates with the existing Vulkan renderer via its Vulkan backend. TDD is temporarily suspended for this feature per user direction.

**Performance Goals**: 60 fps minimum with debug overlay active; debug overlay adds <1 ms per frame

**Constraints**: Vulkan-capable GPU required; ImGui must integrate with existing Vulkan renderer without disrupting triangle rendering; debug layer must not depend on rendering layer internals

**Scale/Scope**: 2 layers in stack (scene, debug), 1 ImGui overlay window, FPS metric, 3 transform controls (position XY, rotation, scale), reset button

**Structure Decision**: A new `debug/` directory houses the `ILayer` interface and `DebugLayer` implementation. The `ILayer` interface provides the common contract for stack-based rendering. `Application` manages the layer stack, iterating through each layer's `render()` method per frame. `IScene` is extended with transform read/write methods so the debug layer can modify triangle properties. `IRenderer` and `VulkanRenderer` are extended with ImGui lifecycle hooks (init, new frame, render draw data, shutdown) but the core rendering pipeline remains unchanged.
