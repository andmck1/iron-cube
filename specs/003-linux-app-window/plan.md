# Implementation Plan: Linux App Window

**Branch**: `003-linux-app-window` | **Date**: 2026-05-19 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/003-linux-app-window/spec.md`

## Summary

Add a platform abstraction layer to iron-core providing window creation and keyboard input handling for Linux via GLFW. Update the application main loop in main.cpp to initialize the platform, create a 1280x720 window titled "Iron Cube", run an event-processing loop, and exit cleanly on window close or Escape key press.

## Technical Context

```text
src/core/
└── src/
    ├── platform/
    │   ├── IPlatform.h          # Platform service interface
    │   ├── IWindow.h            # Window abstraction interface
    │   ├── IInput.h             # Input abstraction interface
    │   ├── Platform.cpp         # Linux platform implementation
    │   ├── Platform.h           # Linux platform implementation header
    │   ├── WindowGLFW.cpp       # GLFW window backend
    │   ├── WindowGLFW.h         # GLFW window backend header
    │   └── InputGLFW.cpp        # GLFW input backend
    └── service/
        ├── ServiceLocator.h     # Service locator header
        └── ServiceLocator.cpp   # Service locator implementation

src/app/
└── src/
    └── main.cpp                 # Updated with main loop

tests/
└── unit/
    ├── test_platform.cpp        # Platform service tests
    ├── test_window.cpp          # Window creation tests
    └── test_input.cpp           # Input handling tests
```

**Structure Decision**: Platform abstraction lives in `src/core/src/platform/` as part of iron-core. Application layer in `src/app/src/main.cpp` consumes the platform via service locator. Linux-only implementations use GLFW backend. Interfaces are defined as headers for future multi-platform extension.
